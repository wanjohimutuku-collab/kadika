# 002 — Database schema decisions where §5 is ambiguous

Status: accepted (Phase 0)

- **UUIDv7** is generated in the application (`uuid` v7 via Drizzle `$defaultFn`), since Postgres 16 has no native function.
- **Enums** not specified in §5 use these defaults: `role_global` user|admin; `event_status` draft|active|completed|archived; `event_plan` free|paid; `language` sw|en; `invite_channel_pref` whatsapp|sms|print|mixed.
- **`events.signing_key_id`** is a plain UUID with no FK, because `signing_keys.event_id` already references `events` (circular). Integrity is enforced in the service layer (Phase 1).
- **`event_members`, `audit_log`** get a surrogate `id` plus `created_at`/`updated_at` to follow "all tables have id and timestamps". `event_members` has a unique `(event_id, user_id)` index.
- **`message_log`** has no `provider`-status enum; `status` is free text because provider vocabularies differ.
- **`scan_log.scanned_at`** is device time; `synced_at` is server time.
- **`guests.deleted_at`** is a soft delete; `guests.phone_e164` is not unique (family members may share a phone).
- Indexes from §5 are present; `users.phone_e164` and `payments.provider_ref` are unique.
- **Migrations:** generated by `drizzle-kit generate` into `packages/db/drizzle`; applied by `pnpm db:migrate` (dev) or `node dist/migrate.js` in the API image (release step). `drizzle-kit migrate` itself is not used because the image would need drizzle-kit.
- **Seed:** `pnpm db:seed` creates a demo organizer, event and 3 guests (placeholder key material; real keys in Phase 1). Idempotent.
